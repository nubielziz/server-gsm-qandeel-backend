# P2.1 runtime-core

Phase 2, feature 1. Read `_common.md` first. Work in the main checkout `/home/saifi/gsm-project/backend`.
Decisions: 008 (contract layer), 011 (money), 012 (logging), 013 (config), 014 (testing), 015 (metrics, health),
016 (layout), 018 (pipeline order), 028 (errors). Wire conventions: `docs/contract/ALIGNMENT.md` §§ 1, 2, 5, 6.

This feature lays the runtime every route will use. Later features add the database (P2.3), Redis/BullMQ (P2.4),
security guards (P2.5) and OpenAPI/Scalar + lint (P2.2), so design the seams they plug into, but do not build them.

## Build

1. **Dependencies**: `nestjs-pino`, `pino`, `pino-http`, `@fastify/cookie`, `@fastify/helmet`, `uuidv7`, `decimal.js`;
   dev `pino-pretty`. (`@fastify/cors` comes with the Fastify platform.)
2. **Config** `src/config/`: `env.ts` = one zod schema for every variable known today, parsed once; production
   requires the secrets, development/test get safe defaults. Variables: `NODE_ENV`, `PORT`, `HOST`, `LOG_LEVEL`,
   `TRUST_PROXY` (hop count or CIDR list), `BODY_LIMIT_BYTES`, `CORS_ORIGINS` (comma list of exact origins),
   `ERRORS_BASE_URL`, `DATABASE_URL`, `DATABASE_URL_TEST`, `DATABASE_POOL_MAX`, `REDIS_QUEUE_URL`, `REDIS_CACHE_URL`,
   `BULL_PREFIX`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
   `S3_FORCE_PATH_STYLE`, `CSRF_SECRET`, `CSRF_COOKIE_DOMAIN`, `COOKIE_SECURE`, `TOKEN_PEPPER`, `ENCRYPTION_KEYS`,
   `ENCRYPTION_ACTIVE_KID`, `METRICS_TOKEN`, `WORKER_METRICS_PORT`, `PROMETHEUS_URL`, `SENTRY_DSN`,
   `REFERENCE_DOCS` (`open|staff|off`, default `open` outside production, `staff` in production). `config.module.ts`:
   a global module providing the frozen typed config under `APP_CONFIG`; a redacted summary helper for the boot log.
   Update `.env.example` to list every variable.
3. **Logging** (`src/infra/logging/`): pino through nestjs-pino with the Fastify adapter (check Context7 for the
   wiring), JSON in production, pretty in development, `warn` in tests; the redaction paths and the email/phone/IMEI
   masking serializers of decision 012; the request id bound to every request log line.
4. **Request id**: Fastify `genReqId` keeps an incoming `X-Request-Id` of ≤ 64 characters from `[A-Za-z0-9._-]`,
   otherwise makes a UUIDv7; every response (errors included) carries `X-Request-Id`. Expose a small helper that
   returns the current request id (for outbox payloads and jobs later).
5. **Errors** (`src/common/errors/`): `catalog.ts` = every code of `docs/contract/error-codes.md` with its status and a
   fixed, plain-English `title` you write (one short sentence, user-facing, no jargon); `AppError(code, { detail?,
   errors?, cause? })`; a global exception filter producing problem+json exactly per decision 028
   (`type` = `${ERRORS_BASE_URL}/<code in kebab-case>`, `title`, `status`, `code`, `detail`, `errors?`, `requestId`).
   Map: `AppError`; contract validation (step 6) → `422 VALIDATION_FAILED`; Nest `HttpException` and Fastify errors →
   `400 BAD_REQUEST` (malformed JSON), `413 PAYLOAD_TOO_LARGE`, `415 UNSUPPORTED_MEDIA_TYPE`, `404 NOT_FOUND`
   (unknown route, via Fastify's not-found handler); anything else → `500 INTERNAL_ERROR` with a generic detail
   (no stack or message in production; the full error is logged with the request id). The filter increments
   `api_errors_total{surface,method,route,status,code}` (step 8). Provide a seam for a surface-specific envelope:
   routes under `/api/index.php` will register their own formatter later (Dhru, decision 026); default problem+json.
   A unit test proves `catalog.ts` and `error-codes.md` list the same codes with the same statuses.
6. **Contract layer** (`src/common/contract/`), decision 008:
   - `zod.ts`: shared schemas with JSON-Schema metadata `x-gsm-alias` (`zMoney` = `^-?\d+\.\d{4}$` string, alias
     Money; `zDecimal`; `zIsoDateTime` = ISO UTC with milliseconds and Z, alias IsoDateTime; `zId` = positive integer
     ≤ 2^53 − 1 (`Number.MAX_SAFE_INTEGER`), alias Id; `zDateOnly` = `YYYY-MM-DD`; `zJsonObject`). `.meta({ 'x-gsm-alias': … })` reaches
     `z.toJSONSchema` output (verified).
   - `defineRoute({ key, summary, description, tags, surface, access, permission, params, query, body, headers,
     success: { status, schema?, contentType? }, errors: [codes], examples })` → a frozen contract object, registered
     in a global registry (duplicate key throws). `key` is the manifest key (`'GET /admin/staff/:id'`); the Nest path
     is derived from it. Non-JSON successes (CSV, PDF, HTML) declare `contentType`.
   - `@Route(contract)`: applies the Nest method + path, `@HttpCode(success.status)`, the validation pipe, the response
     interceptor and the @nestjs/swagger metadata (operation, params, query, body JSON Schema, the success response
     with its schema and example, one problem+json response per error status listing its codes, security per
     `access`). Strip zod's `$schema` and the long ISO `pattern` when a `format: date-time` is present.
   - Validation pipe: params, query, body (and declared headers) parsed with the contract's schemas; failure → `422
     VALIDATION_FAILED` with one `errors[]` item per zod issue `{ field: dotted path, code: zod issue code, message }`.
   - Response interceptor: the handler result is parsed with the success schema (strip unknown keys) before it is
     sent; a mismatch is logged with details and answered `500 RESPONSE_CONTRACT_VIOLATION`. Status 204 sends no body.
   - Lists: `listQuery({ sorts, filters: { field: { type, ops } }, search, defaultSort, maxPage })` builds the zod
     schema for the simple-rest dialect of ALIGNMENT § 2 (`_start`, `_end`, `_sort`, `_order`, `q`, field filters,
     repeated keys = IN, suffixes `_ne/_gte/_lte/_gt/_lt/_like`, strings or arrays accepted, booleans, ISO times) and
     returns a typed parsed object (range, sort list, filters with operators, search text); unknown sort or filter →
     422 naming the parameter. A handler returns `{ rows, total }`; the list interceptor answers the array and sets
     `x-total-count`. Default page 0–25, maximum page 1000.
   - A short `src/common/contract/README.md`: how to write a contract (example route).
7. **Money helper** `src/common/money.ts` (decision 011): `Money` on decimal.js, scale 4, ROUND_HALF_UP; `of`, `add`,
   `sub`, `mul`, `pct`, `neg`, `cmp`, `isZero`, `toWire()` → `"12.4900"`; parsing rejects floats/NaN. Unit-tested.
8. **Metrics** (`src/infra/metrics/`): one prom-client registry per process; default metrics;
   `http_request_duration_seconds` (labels method, route template, status) via a Fastify `onResponse` hook;
   `api_errors_total` (step 5). `GET /metrics` (map route, module health, contract with `contentType: text/plain`):
   allowed with `Authorization: Bearer <METRICS_TOKEN>` when that is set, otherwise only from loopback/private source
   addresses; else `403 FORBIDDEN`.
9. **Health** `GET /health` (map route, module health): `200 { status: 'ok'|'degraded'|'down', checks?: { <name>:
   'ok'|'down' } }` always (frontend contract); `?strict=1` answers 503 with the same body when status is not ok.
   Indicators plug in through a registry (`HealthIndicator { name, critical, check() }`): any critical down → `down`,
   only non-critical down → `degraded`. P2.3/P2.4 register Postgres (critical) and the two Redis roles (non-critical);
   for now the registry may be empty (→ ok). No versions, hostnames or error texts in the body.
10. **Modules and bootstrap** (decision 016): create the 12 module folders `src/modules/<id>/` (ids from
    `scripts/module-map.mjs`) each with `<id>.module.ts` and `index.ts` (empty public API for now); the health module
    holds `/health` and `/metrics`. `src/app.module.ts` imports config, logging, metrics and the 12 modules.
    `src/main.ts`: Fastify adapter (`trustProxy` from config, body limit, `genReqId`), `@fastify/cookie`,
    `@fastify/helmet` (CSP relaxed only for `/docs` and `/reference`, added by P2.2), CORS per ALIGNMENT § 6 (exact
    origins, credentials, exposed headers, preflight before everything), the exception filter, shutdown hooks,
    listen. `src/worker.ts` + `src/worker.module.ts`: Nest application context with config, logging and metrics,
    shutdown hooks, and its own `/metrics` HTTP listener on `WORKER_METRICS_PORT` (no BullMQ yet).
11. **Tests and scripts**: `bunfig.toml` (`[test]` preload `test/setup.ts` that sets `NODE_ENV=test`; timeout 15 s);
    unit tests next to the code (`*.spec.ts`) and HTTP tests in `test/integration/` using `@nestjs/testing` +
    Fastify `inject`: validation → 422 shape, response strip and violation, list parsing (operators, repeats,
    whitelist 422, `x-total-count`), problem+json for AppError / unknown error / unknown route / malformed JSON / 413,
    request id kept and generated, CORS headers on an error response, health ok / degraded / down / strict 503,
    metrics guard, config failure in production. `package.json` scripts: `test`, `test:unit`, `test:integration`,
    `start:worker`, `dev:worker`; keep `check` passing.
