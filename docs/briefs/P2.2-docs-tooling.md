# P2.2 docs-tooling

Phase 2, feature 2. Read `_common.md` first. Work in the worktree path given in your prompt (a checkout of branch
`feat/backend-p2-docs`, already containing P2.1). Decisions: 008 (contract layer, OpenAPI metadata), 009 (contract
sync: generated documents are committed), 016 (layout, module boundaries), 017 (public and internal documentation),
013 (no `process.env` outside config). The contract layer of P2.1 (`src/common/contract/`) already applies the
@nestjs/swagger metadata per route; this feature turns it into documents, pages, lint rules and contributor docs.

## Build

1. **OpenAPI documents** (`src/modules/platform/docs/`, the platform module owns the map routes `GET /openapi.json`
   and `GET /docs`):
   - Build the document with `SwaggerModule.createDocument` on the Nest app (OpenAPI 3.1 via
     `DocumentBuilder().setOpenAPIVersion('3.1.0')`), then post-process: drop zod's `$schema`, keep `x-gsm-alias`,
     add security schemes `staffSession` (cookie `gsm_admin_session`), `merchantSession` (cookie
     `gsm_client_session`), `customerSession` (cookie `gsm_store_session`), `apiKey` (HTTP bearer), `webhookSignature`
     (documented header, not callable), plus the other names in `SECURITY_SCHEME` (`src/common/contract/openapi.ts`),
     tags = surface + map group. Pass `autoTagControllers: false` to `SwaggerModule.createDocument` (tags come from
     the contracts) and set no document-level `security` (public operations carry none; each operation has its own).
     `@Route` already writes `x-gsm-key`, `x-gsm-access` and `x-gsm-permission`; add `x-gsm-surface` so documents can
     be filtered.
   - Internal document: every route. Public document: only operations whose surface is `v1`, plus (when they exist)
     the Dhru reference operation and the outgoing events as OpenAPI 3.1 `webhooks` (decision 017); build the filter
     now and test it with fixture contracts.
   - Routes: `GET /openapi.json` (public document, map route, contract with JSON content) and `GET /docs` (Scalar
     page on the public document, map route, `contentType: text/html`) through `@scalar/nestjs-api-reference`
     (`apiReference({ content, withFastify: true })`, CDN version pinned). Internal: `GET /reference/openapi.json` and
     `GET /reference` (not map routes: register them as documentation routes the route-parity test will allow
     explicitly). `REFERENCE_DOCS` = `open` serves them, `off` answers 404, `staff` asks a guard token
     `REFERENCE_DOCS_GUARD` that P2.5 will provide (until then `staff` behaves like `off`).
   - Helmet: relax the CSP only for `/docs` and `/reference` (Scalar's CDN scripts, styles and fonts; connect-src
     self).
   - `scripts/gen-openapi.ts`: builds both documents without connecting to any infrastructure (create the Nest app,
     do not call init/listen) and writes `docs/contract/openapi.json` and `docs/contract/openapi.public.json`
     (stable key order, trailing newline); `--check` fails when the committed files differ. Scripts
     `docs:openapi`, `docs:openapi:check`; add the check to `bun run check`.
2. **Lint and format**: ESLint flat config with typescript-eslint (type-aware, a pragmatic strict set incl.
   `no-floating-promises`, `no-misused-promises`, `no-explicit-any` as error with inline-disable reasons allowed),
   `eslint-plugin-jsdoc` (JSDoc required on every exported function, class, method, interface and type alias, with a
   description; `require-param`/`require-returns` where meaningful), a module boundary rule (code in
   `src/modules/<a>/` may import another module only through `src/modules/<b>/index.ts`; `src/common` and
   `src/infra` never import from `src/modules`; exactly two exceptions, both for the Drizzle schema of decisions
   016/027: a module's `db/schema.ts` may import another module's `db/schema.ts` for foreign keys, and
   `src/infra/db/schema.ts` re-exports every module's `db/schema.ts`; health indicators register with
   `src/infra/health`, so they need no exception), `process.env` only under `src/config`, no `console` in `src`
   (logger instead), and `eslint-config-prettier`. Do not enable `consistent-type-imports` auto-fix (it would break
   Nest DI). Scripts `lint`, `lint:fix`, `format`, `format:check`; add `lint` to `bun run check`. Make the existing
   code pass (fix it, do not weaken the rules; justified inline disables only). The P2.1 review found about 57
   exported types/interfaces whose TSDoc has a summary but no "Why" line (`_common.md`), e.g. in
   `src/common/contract/define-route.ts`, `list-query.ts`, `src/config/env.ts`, `src/common/errors/catalog.ts`: add
   them while you are there.
3. **Module READMEs**: `src/modules/<id>/README.md` for the 12 modules: purpose, owned tables (with their English
   description), routes (from `docs/slices/<id>.json`), scenarios that touch the module, and sections to fill as the
   module grows (jobs and schedules, events produced/consumed, cache keys, permissions). A small script may scaffold
   them once; the files are then maintained by hand.
4. **CONTRIBUTING.md**: how to add an endpoint end to end (manifest check → contract → controller → service →
   repository → tests → regenerate docs → checks), how to add a job (queue, idempotency, retry policy,
   `docs/queues.md`), how to add a cache key (`CacheKeys`, `docs/cache-keys.md`, invalidation after commit), how to
   add a money event (builder, unit test with exact numbers, decision 024), how to run everything locally.
5. **CI script** `scripts/ci.sh`: `bun install --frozen-lockfile`, start the compose services if needed, run
   `bun run check` (typecheck, lint, tests, routes, contract and OpenAPI checks); exits non-zero on any failure.
   Document it in the README. (No hosted CI file: the hosting is not decided.)

## Out of scope
Database, Redis, guards, the Dhru operation itself, real REST v1 routes, the contract parity tests (P2.7).

## Done when
`bun run check` is green including lint and `docs:openapi:check`; `GET /docs` renders Scalar on the public document;
`GET /reference` renders the internal one with `REFERENCE_DOCS=open`; tests cover the public/internal filter, the
documentation routes, the `off` mode and the generator's `--check`.
