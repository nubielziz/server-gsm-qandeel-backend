# P2.4 infra

Phase 2, feature 4. Read `_common.md` first. Work in the worktree path given in your prompt (branch
`feat/backend-p2-infra`, containing P2.1–P2.3). Decisions: 004 (S3), 006 (two Redis roles), 007 (argon2), 015
(metrics, Prometheus), 019 (encryption, token hashing, webhook signatures), 020 (outbox and queues), 021 (rate
limiting), 022 (caching), 023 (outbound HTTP). The spike (`spike/bun-compat/`) shows working code for most pieces
under Bun; this feature makes them production-grade and then deletes the spike.

The brief is built as two features: **P2.4a** (pass A: items 1–5 and their tests) and **P2.4b** (pass B: items 6–10).
Your prompt says which.

## Build

1. **Redis** (`src/infra/redis/`): one cache client and one queue producer client per process from config (decision
   006: producers `enableOfflineQueue: false`; a factory for worker connections with `maxRetriesPerRequest: null`);
   `error` listeners logging without secrets; connect in `onModuleInit` (constructors never connect, so the OpenAPI
   generator can build the app offline); close in `onApplicationShutdown`. Health indicators (non-critical, registered
   with `HealthRegistry` from `src/infra/health`): `redis` (cache) and `redis_queue` (also reports used memory against
   maxmemory).
2. **CacheService** (`src/infra/cache/`, decision 022): `getOrLoad(key, ttlSeconds, loader, { lockMs?,
   staleWhileRevalidate?, negativeTtlSeconds? })` with ±15% TTL jitter, in-process coalescing, a `SET NX PX` lock for
   hot keys, optional stale-while-revalidate, negative caching; `del`, `delByPrefix` (SCAN, never KEYS), version keys
   (`bumpVersion(name)`, `versioned(name, key)`); values JSON, refuse > 100 KB. `CacheKeys`: the only way to build
   keys (`gsm:{env}:{module}:{entity}:{id}[:v{n}]`); `docs/cache-keys.md` lists every builder (owner, TTL,
   invalidation) and a test fails when a builder is missing there. Cache hit/miss counters per key family.
3. **RateLimitService** (`src/infra/rate-limit/`, decision 021): `rate-limiter-flexible` on the cache Redis; named
   limiters configured in one place (per IP, per API key with a per-key limit, sign-in by email+IP with block after
   failures, token lookups); `consume(name, key, points?)` → `{ allowed, remaining, limit, retryAfterSeconds }` and a
   helper that throws `AppError('RATE_LIMITED')` carrying `Retry-After`; a Redis semaphore (`acquire(name, max,
   ttlMs)` / `release`) for per-supplier concurrency.
4. **Crypto** (`src/infra/crypto/`, decision 019): AES-256-GCM keyring (`ENCRYPTION_KEYS`, `ENCRYPTION_ACTIVE_KID`,
   AAD `<table>.<column>`, text format `v1:<kid>:<iv>:<tag>:<ct>`), `hashToken()` = HMAC-SHA256 with `TOKEN_PEPPER`
   (hex), `randomToken(bytes)` (base64url), constant-time compare, `PasswordHasher` over `@node-rs/argon2` (argon2id,
   parameters from config; default argon2id default algorithm, assert the `$argon2id$` prefix), webhook signing
   (`sign(secret, timestamp, body)` → `t=<unix>,v1=<hex>`, `verify` with a 5-minute window). `scripts/bench-argon2.ts`
   prints the time per hash for candidate parameters (target 50–150 ms).
5. **Storage and HTTP**: `StorageService` (`src/infra/storage/`, decision 004): put (buffer or stream, content type,
   sha256, size limit), get stream, head, delete, presigned GET with expiry; health indicator `storage`
   (non-critical). `httpRequest()` (`src/infra/http/`, decision 023): explicit `timeoutMs` (required), no retries, no
   redirects, duration metric and a redacted log line with the request id; `assertPublicHttpUrl(url, { httpsOnly })`
   resolving DNS and refusing private, loopback, link-local, multicast and reserved ranges (v4 and v6).
6. **BullMQ base** (`src/infra/queues/`, decision 020): the queue registry (names, default job options, concurrency
   per queue, prefix `${BULL_PREFIX}` default `gsm:<env>:bull`); producers with `error` listeners; a processor
   registration API modules use (`@QueueProcessor('supplier-dispatch')` or an explicit registry) that only the worker
   process starts; Worker connections from the item-1 factory; graceful close in `onModuleDestroy` (workers) before
   connections close in `onApplicationShutdown`; `JobSchedulers` registry upserted on every worker boot
   (`upsertJobScheduler`, idempotent); retries with exponential backoff + jitter, `UnrecoverableError` for permanent
   failures; `removeOnComplete { age: 24 h, count: 10 000 }`, `removeOnFail { age: 14 days }`; BullMQ gauges per
   queue and state on scrape. `docs/queues.md`: one section per queue (jobs, payload, idempotency key, retry policy,
   schedule), filled for what exists now and extended by every feature.
7. **Job runs**: `JobRunsService` writes `job_runs` (start → running, finish → status, duration, processed, result
   JSON, error) around every scheduled or manual run; a wrapper processors use. `job_runs` belongs to the health module
   (`scripts/module-map.mjs`), so the service and the wrapper live in `src/modules/health/` and are exported from its
   `index.ts`; module processors wrap their scheduled work with it. `src/infra/queues` must not import it.
8. **Outbox** (`src/modules/platform` owns `outbox_events`; put the service in `src/modules/platform/outbox/` and
   export it from the platform module's `index.ts`): `OutboxService.add(tx, { type, aggregateType, aggregateId,
   payload })` (ids only; adds the current request id to the payload metadata) plus `pg_notify('outbox', id)` in the
   same transaction; the relay (worker only): a scheduler every second and a `LISTEN outbox` wake-up, selects pending
   rows `ORDER BY id LIMIT 100 FOR UPDATE SKIP LOCKED`, adds one job per row with `jobId = outbox-<id>` to the queue
   mapped from the event type (a registry modules extend), sets `processed_at` in the same transaction, counts
   attempts; metrics for lag and throughput.
9. **Prometheus**: add a `prometheus` service to `compose.yaml` (pinned image) with `docker/prometheus/prometheus.yml`
   scraping the API (`host.docker.internal:3000/metrics`, bearer `METRICS_TOKEN`) and the worker
   (`host.docker.internal:<WORKER_METRICS_PORT>/metrics`), `extra_hosts: host.docker.internal:host-gateway`;
   `PROMETHEUS_URL` default `http://localhost:9090` in `.env.example`.
10. **Retire the spike**: delete `spike/`, the `spike` script and the `postgres` and `argon2` dependencies; update the
    README and decision 001's last bullet. The integration tests must now prove what the spike proved, under Bun:
    BullMQ worker SIGTERM with an active job (the job finishes, then connections close), jobId de-duplication, an
    idempotent scheduler upsert, a producer failing fast while Redis is down at startup, a worker resuming after a
    queue-Redis restart (gate this one behind `GSM_TEST_DOCKER=1`, it restarts the compose container), the outbox
    relay moving a committed row exactly once and ignoring a rolled-back one. (S3, cache stampede, rate limiter,
    crypto, signature window, SSRF guard, HTTP timeout and producer fail-fast are covered by P2.4a.)

## Done when
`bun run check` is green; `spike/` is gone; `docs/queues.md` and `docs/cache-keys.md` exist; the health endpoint
reports `redis`, `redis_queue`, `storage` and Postgres; `bun src/worker.ts` starts the outbox relay and stops cleanly.
