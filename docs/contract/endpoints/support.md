- late=true: Overdue.
- assigneeId=<me>: Mine.

Sort: _sort=late,updatedAt&_order=desc,desc; the Resolved filter sends updatedAt desc only (lib/filters.ts:152-175).
Counts, each with _start=0&_end=1, every 30 s: status=new&status=open&status=pending; status=new; late=true; status=resolved (hooks/useTicketCounts.ts:18-34).
Customer page: requesterType=customer&requesterId=<id>&_sort=updatedAt&_order=desc&_start=0&_end=10 (hooks/useCustomerTickets.ts:8-16).
Palette: q&_start=0&_end=3&_sort=updatedAt&_order=desc.

- orderId or null, category (one of 8 words), priority high|normal|low.
- status: only new|open|pending|resolved (the stored pending_customer is sent as pending: status codec, B112; closed is removed from the stored vocabulary so it can never reach the console). Any other word crashes the badge (TicketStatusBadge.tsx:7-8).

The map computes sla_due_at by category at creation (b2c-ticket step 2), while the demo uses priority targets of 2h, 8h and 24h. Proposal: the category sets the default priority; sla_due_at = time of the last customer message + the priority's target, recomputed when the customer writes or the priority changes, and null after a public staff reply. → Proposal accepted.
